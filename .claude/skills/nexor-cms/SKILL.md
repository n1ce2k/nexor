# NEXOR CMS

Собственная CMS на Laravel: админ-панель с инфоблоками, свойствами произвольных типов, ролями и правами. Написана с нуля — **без Filament, Orchid, spatie/laravel-permission и прочих готовых решений**. Это осознанное решение владельца проекта, не предлагай их заново.

Ядро оформлено как composer-пакет **`n1ce2k/nexor-cms`** (namespace `Nexor\Cms`). Исходники — в `packages/nexor-cms`, приложение подключает их через path-репозиторий и работает из `vendor/n1ce2k/nexor-cms`. **Правь исходники в `packages/`, а не в `vendor/`.**

## Первым делом

У проекта две админки поверх одного ядра: Blade на `/admin` и Vue-SPA на `/admin/vue`. Правишь Vue — читай `references/vue-panel.md`.

Перед любой правкой прочитай `references/architecture.md` — там модель данных и то, как устроены свойства. Перед правкой экранов админки прочитай `references/ui-kit.md` — там каталог готовых Blade-компонентов; почти всегда нужный уже есть.

| Файл | Когда читать |
|---|---|
| `references/architecture.md` | Инфоблоки, свойства, EAV, разделы-дерево, права |
| `references/ui-kit.md` | Любой экран админки, формы, таблицы, фильтры |
| `references/conventions.md` | Именование, структура классов, тесты, что где лежит |
| `references/vue-panel.md` | Vue-админка на /admin/vue, JSON API, реестр расширений |

## Правила, которые нарушать нельзя

**Права на контент привязаны к id инфоблока, а не к коду.** `Iblock::permissionCode('view')` возвращает `iblock.{id}.view`. Так переименование инфоблока не отбирает права у ролей. Никогда не переводи это на символьный код.

**Тип свойства сам говорит, в какой колонке лежит значение.** `PropertyType::column()` — единственный источник правды. Не пиши `match` по типу свойства в новых местах: спроси у энума.

**Никаких новых зависимостей без спроса.** Проект намеренно держится на ядре Laravel. Если кажется, что нужен пакет — сначала спроси.

**Не создавай Blade-компонент, не посмотрев `packages/nexor-cms/resources/views/components/admin/`.** Их там 27, и нужный обычно уже есть.

## Как добавить новую сущность в админку

Всё внутри `packages/nexor-cms`:

1. Миграция в `database/migrations`, модель в `src/Models` — не забудь `protected static function newFactory()`.
2. Права — добавь группу в `Nexor\Cms\Support\Permissions::definitions()`, прогони `php artisan nexor:permissions`.
3. Пункт меню — `Nexor\Cms\Support\Navigation::forUser()`, там же проверка права.
4. Контроллер в `src/Http/Controllers`, Form Request в `src/Http/Requests`.
5. Роут в `routes/admin.php` через хелпер `$guard(...)` — он навешивает `nexor.permission:<префикс>.view|create|update|delete` на нужные методы ресурса.
6. Экраны — `resources/views/admin/<сущность>/{index,form}.blade.php`, возвращать как `view('nexor::admin.<сущность>.index')`.
7. Тест — добавь URL в `AdminScreensTest`, плюс отдельный feature-тест на логику.

## Ловушки, на которые уже наступали

**Экранированные кавычки внутри Blade-атрибута ломают компиляцию.** `x-data="{ ... querySelectorAll('input[name=\'foo[]\']') ... }"` даёт ParseError. Вешай `data-*` атрибут и селекти по нему.

**Пакет не должен знать класс пользователя.** Только `Nexor::userModel()` / `Nexor::newUser()` и тип-хинт `NexorUser`; параметр `{user}` резолвится явным `Route::bind` в провайдере.

**Фабрики и модели пакета объявляют `$model` и `newFactory()`** — стандартный резолвер Laravel ищет фабрику в неймспейсе приложения и на пакете промахивается с ошибкой вида `Class "App\Role" not found`.

**`Route::resource(...)->middleware([...])` вешает все middleware на все методы.** Ассоциативный массив `['index' => ...]` не работает как ожидается. Нужен `->middlewareFor('index', ...)` — это и делает хелпер `$guard`.

**Интерактивные artisan-команды вешают сессию.** Всегда `-n` / `--no-interaction`. `php artisan db:table` без аргумента ждёт ввода вечно.

**Настройки кэшируются навсегда.** После прямого UPDATE в таблицу `settings` мимо модели — `Cache::forget(Setting::CACHE_KEY)`.

**Сидеры не перетирают уже сохранённые значения настроек** — только метаданные (подпись, группу, сортировку). Если нужно поменять само значение — `Setting::put()`.

## Проверка работы

```bash
php artisan test --compact
vendor/bin/pint --dirty --format agent
```

`AdminScreensTest` открывает каждый экран админки и рендерит форму элемента со свойствами всех типов — он ловит сломанные шаблоны, которые обычные тесты не трогают. Если добавил экран, добавь его туда.

## Окружение

MySQL из OpenServer: `127.0.0.1:3306`, `root`, пароль пустой, база `nexor`. PHP CLI — отдельный, `C:\php\php.exe`, не тот, что в OpenServer; расширения включаются в `C:\php\php.ini`. Тесты идут на sqlite в памяти. Вход в админку — `admin@nexor.local`.
