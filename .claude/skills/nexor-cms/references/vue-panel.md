# Vue-панель

**Vue-панель — основная админка проекта.** SPA на Vue 3 открывается на `/admin`.

Blade-версия никуда не делась: она переехала на `/admin/classic` и работает как раньше. Какая из двух владеет голым `/admin`, решает `config('nexor.panel.default')` — `vue` (по умолчанию) или `blade`; в `.env` это `NEXOR_PANEL`. Имена маршрутов при переключении не меняются, поэтому ссылки в шаблонах остаются рабочими.

Ловушка: catch-all `admin/{any?}` съедает всё под префиксом, поэтому группа API регистрируется в провайдере **раньше** группы админки. Если поменять порядок — `/admin/api/*` перестанет отвечать JSON.

## Где что лежит

```
packages/nexor-cms/
  routes/api.php                    JSON API, префикс /admin/api, имена admin.api.*
  src/Http/Controllers/Api/         контроллеры API (наследуют ApiController)
  src/Http/Resources/               Eloquent API Resources
  src/Http/Controllers/PanelController.php   отдаёт HTML-оболочку SPA
  resources/views/admin/panel.blade.php      сама оболочка
  resources/js/panel/
    main.js                         точка входа, публикует window.Nexor
    registry.js                     точки расширения
    api.js                          обёртка над fetch: CSRF, ApiError, FormData
    router.js
    App.vue
    layouts/AdminLayout.vue
    stores/{session,ui}.js
    composables/{useForm,useNavigation}.js
    components/ui/N*.vue            UI-кит
    components/fields/              редакторы свойств + PropertyField
    pages/                          экраны
```

## Как это работает

Форма элемента **не описана в коде**. Страница запрашивает `GET /admin/api/iblocks/{id}/schema`, получает список свойств и для каждого достаёт компонент из реестра по типу. Добавили новый тип свойства — зарегистрировали компонент, и форма его подхватила.

Ответы API: ресурс, возвращённый из контроллера напрямую, обёрнут в `data`; ресурс, вложенный в `response()->json([...])`, — **не обёрнут**. Поэтому `bootstrap`, `dashboard` и `schema` отдают плоские массивы, а списки — `{ data, meta }`.

Значения свойств уходят через `multipart/form-data`, потому что файловые свойства несут настоящие `File`. У файловых свойств значение в форме — объект `{ stored, remove, added }`, у остальных — скаляр или массив.

## Точки расширения

Всё через `window.Nexor` **до** монтирования. Свой бандл подключается в `config('nexor.panel_extensions')` — он грузится раньше `main.js`.

```js
window.Nexor.ready((nexor) => {
    // свой редактор для типа свойства
    nexor.registerField('geo', MyMapField);

    // своя страница + пункт меню
    nexor.registerPage({
        path: 'reports',
        name: 'reports',
        component: Reports,
        permission: 'reports.view',
        menu: { label: 'Отчёты', icon: 'chart', group: 'Контент' },
    });

    // своя ячейка в списке элементов конкретного инфоблока
    nexor.registerColumn('colors', 'HEX', SwatchCell);

    // реакция на события панели
    nexor.on('element.saved', ({ element }) => console.log(element));
});
```

Контракт компонента-поля: props `modelValue`, `property`, `options`, `invalid`; эмитит `update:modelValue`. Множественность и обёртку с подписью берёт на себя `PropertyField` — само поле всегда работает с одним значением.

## Визуальный редактор

`ui/NEditor.vue` — обёртка над Quill (тема snow, перекрашенная в токены панели). Наружу отдаёт обычную строку HTML, поэтому подставляется прямо вместо `<textarea>`.

`ui/NHtmlInput.vue` добавляет к нему переключатель «Исходный код»; именно он стоит в описании инфоблока, в анонсе и подробном тексте элемента (когда формат — HTML), в письмах и в настройках типа `html`. Свойства инфоблока с типом `html` рисует `fields/FieldHtml.vue` — тот же `NHtmlInput`, зарегистрированный в реестре полей.

## Вкладки формы элемента

`ElementForm.vue` не описывает вёрстку конкретного инфоблока: он берёт `form_tabs` и `form_fields` из схемы и раскладывает поля по вкладкам. `components/FormLayoutEditor.vue` («Настроить форму») позволяет переименовать вкладки, добавить и удалить их, переставить и раскидать поля — раскладка сохраняется в инфоблоке. Если валидация упала на скрытой вкладке, форма сама на неё переключается и помечает точкой.

## Разделы меню

| Группа | Пункты |
|---|---|
| Контент | инфоблоки, сгруппированные по типу |
| Структура | Инфоблоки, Типы инфоблоков |
| Настройки | Почта (SMTP, шаблоны), Инструменты (SQL, PHP) |
| Администрирование | Пользователи, Роли и права, Настройки сайта, Журнал действий |

Пункт «Инструменты» показывается только супер-администратору — так же, как проверяет сервер.

## Что уже готово и чего нет

Готово: рабочий стол, инфоблоки, свойства, элементы, пользователи, роли, типы инфоблоков, настройки сайта, SMTP, почтовые шаблоны, журнал, консоль разработчика.

Не готово: разделы инфоблоков и профиль — они пока только в Blade-админке. API для разделов уже есть, нужен только экран.

## Настройки как редактируемые поля

`SettingsEditor.vue` рисует одну или несколько групп настроек и позволяет добавлять свои поля прямо из интерфейса — тип, ключ, подсказку, варианты для списка. Системные настройки (те, что читает код CMS) можно править, но не удалять.

Тип `password` шифруется на сервере, а в браузер уходит маска `••••••••`. Если сохранить маску обратно — значение не меняется.

## Консоль разработчика

`SQL запрос` и `PHP-строка` выполняют присланный текст. Ограничения намеренно жёстче остальной панели:

- только супер-администратор — это **не** выдаваемое право, его нельзя дать через экран ролей;
- рубильники `NEXOR_TOOLS` и `NEXOR_TOOLS_PHP` в `.env`, по умолчанию выключены;
- каждый запуск пишется в журнал действий вместе с исходным текстом.

На боевом сервере оба рубильника держать выключенными.

## Вход без пароля для отладки

`php artisan nexor:login-link` печатает подписанную одноразовую ссылку в панель — ей можно открыть админку в браузере, не вводя пароль. Нужна для визуальной проверки и скриншотов.

Ограничения: не работает в production вообще, требует `NEXOR_LOGIN_LINK=true`, ссылка подписана и живёт минуты, каждое использование пишется в журнал. Ссылка привязана к хосту из `APP_URL` — открывать её надо на том же домене, иначе подпись не сойдётся.

Ловушка: параметр маршрута назван `{account}`, а не `{user}`, потому что `{user}` глобально забиндён на модель пользователя для CRUD-экранов.

## Проверка

Экраны SPA не покрываются PHPUnit — вместо этого протестирован API, через который панель работает: `tests/Feature/PanelApiTest.php`. Добавляя эндпоинт, добавь туда тест.

```bash
php artisan test --filter=PanelApiTest
php artisan test --filter=PanelFeaturesTest
npm run build
php artisan nexor:login-link        # открыть панель в браузере без пароля
```

Пути маршрутов SPA должны быть **абсолютными** — vue-router отвергает относительные на верхнем уровне с ошибкой `Invalid path`. Пути, зарегистрированные хостом через `registerPage`, нормализуются автоматически.
